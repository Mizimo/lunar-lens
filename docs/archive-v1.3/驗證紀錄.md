- 原生介面檢視了行為與事件面板；UI 回呼另有程式測試。沒有把程式送入 Max 的命令稱為實體按鍵或滑鼠端到端驗收。

## 原生量測校準

使用與 DSP 相同的 48 kHz 校準訊號，避免播放器取樣率轉換改變白噪音頻譜。第一次以 44.1 kHz 校準檔送入 48 kHz DSP 時，白噪音重心會受到播放器轉換影響；因此改以實際 DSP 取樣率產生參考訊號，而沒有放寬門檻來適配結果。

| 項目 | 結果 |
| --- | --- |
| 1 kHz 正弦重心 | 1000.0001 Hz |
| 正弦能量 | −23.0116 dBFS，預期約 −23.0103 |
| 同相左右相關 | 1.0000 |
| 反相左右相關 | −0.9985 |
| 反相正弦重心 | 1000.0001 Hz，未因 mono 抵消而消失 |
| 只有左聲道的平衡 | −0.9985 |
| 獨立立體聲白噪音平坦度 | 0.7654 |
| 白噪音重心 | 11995 Hz，48 kHz 下預期約 12000 Hz |

完整結果見 `measurement-calibration.json`。這些數字驗證的是單位與測量，不代表複雜混音中的事件分類已準確。

## 呈現與限制

- `media/transitions-and-events.mp4` 使用專案自有 Demo 的已捕捉測量，由本輪正式渲染器重播，示範六構圖轉場；不是實機 LED 拍攝。
- 原有混音聲音路徑未改；本輪全曲檢查關閉監聽，不宣稱完成實體音訊輸出的聽感驗收。
- 事件信心是啟發式分數，不是校準機率。完整混音不能可靠分離人聲、Pad 或樂器。
- 自訂行為音域使用八個重疊頻帶，是粗音域遮罩；IMPACT 才有獨立連續 Hz 探針。
- 五個行為參數在當次開啟中保存，目前沒有自動跨開啟 preset。
- Launchpad 通訊的檢查結果會在交付時另行說明；這份紀錄不宣稱量到實體 LED 時間。

## 重現

```sh
npm run build
npm test
# 開啟主 patch 與本機測試橋接 tmp/runtime-control.maxpat 後：
python3 scripts/check-measurements.py
python3 scripts/check-behaviour-controls.py
python3 scripts/run-song-check.py /path/to/recording.mp3 localcheck
python3 scripts/verify-song-trace.py localcheck
npm run package
python3 scripts/verify-release.py
```

Python 圖像／音訊診斷另外需要 Pillow／NumPy 和 ffmpeg。正式 Max 運行與 JavaScript 測試不依賴它們。橋接及原始音訊／大型 trace 位於 `tmp/`，不進封裝或 Git；舊輪次紀錄放在 `docs/archive-v*/`。
