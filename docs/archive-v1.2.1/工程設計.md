# 工程設計 · 1.2.1

所有音檔、Demo 與即時输入共用分析與渲染。`LensFeatures`、`LensVisual` 不接收曲名、歌詞、歌曲長度或提示點。進度只用於播放器；播放速度固定 1×。

## 訊號路徑

    sfplay~ / adc~ → 來源選擇 ┬→ gen~ lens_analysis → 24 個同步 snapshot
                             │                       ↓ LensFeatures
                             │                       ↓ LensVisual ← MIDI／滑鼠
                             │                         ├→ v8ui 8×8
                             │                         └→ Pro MK3 RGB SysEx
                             └→ gen~ lens_fx → 可選 vst~ → Master → ±0.98 保護
                                                                    ├→ sfrecord~
                                                                    └→ 監聽開關 → dac~

分析在效果與 Master 之前，不會因觸控延遲或音量推桿而產生假事件。錄音在監聽開關之前，關閉喇叭仍可驗收輸出。

## Native DSP

`scripts/analysis-source.mjs` 生成 Gen codebox。L/R 各自 DC block，通過八個交疊四階 constant-peak-gain 帶通；每段由兩個 RBJ biquad 串聯，依实际 sample rate 計算係數。

名義邊界：30–70、70–140、140–280、280–600、600–1500、1500–3500、3500–7500、7500–16000 Hz。這些是帶通參數，不是磚牆邊界；串聯濾波在名義邊界已有衰減。L/R 功率平均後，八段按中心頻率的 1.5 個週期（8–40 ms）平滑得到 RMS，不先合成 mono，所以反相输入不會消失。

另外增加可調 Impact 帶通：預設 35–160 Hz，下限 20–160、上限 70–400，至少相隔 25 Hz；係數約 100 ms 平滑。可調低頻探針恢復 8 ms 快速 RMS，另外保留 90 ms 背景 RMS、25 ms peak 包絡作診斷。

24 個輸出依序：八個 band RMS、全頻 RMS、全頻 peak、mono RMS、side RMS、Impact fast RMS、Impact slow RMS、Impact peak、九條 DSP 上升描述量。`qmetro 20`、24 路 trigger / snapshot / pack 先更新冷入口再輸出完整訊息。

## 時間與行為

`LensFeatures` 保留三組頻域能量、三條事件計數及五條行為包絡。一般音量參考有下限，約 0.3 s 上升、7 s 回落；各頻域也有自己的較慢參考。絕對安靜門檻和相對能量佔比防止底噪、濾波器裙邊被放大。

**固定八段起音**：保留 1.2 的音訊時鐘 log RMS 上升描述量、6–40 ms 速度平滑、45 ms 短峰保持、JS 局部峰值判斷及各自受限的中位數／MAD 門檻。固定頻段及其事件邏輯沒有改動。

**可調低頻 IMPACT**：`LowImpactDetector` 恢復 1.1 判斷。每次分析更新計算 `max(0, log(1+fast*100) - previousLog) * .02 / dt`。門檻是最近 75 次讀值的 `max(.14, mean*1.5 + stdev*.65) / sqrt(sensitivity)`。同時要求 fast > .002、fast/全頻 RMS > .25、fast/slow > 1.35、起音量過門檻、最短間隔，以及已重新準備。ratio < 1.025 或 fast < .002 才重新準備。調頻後抑制 300 ms 並清空低頻歷史，保持事件計數。這恢復了舊版的密度相關門檻取捨。

第 24 路 DSP 描述量保留供低頻已接受事件的力度計算使用，不再用它決定是否觸發。沒有 1.01 倍放寬條件或短擊補回路徑。

**力度**：事件接受後，由 `1-exp(-rise/.85)` 和該段相對能量加權連續輸出 0–1；不除以門檻。事件先觸發，前 65 ms 允許力度跟隨更大的實測峰值；Renderer 同步補足重量。`bandDynamics[0..7]` 輸出原始能量、novelty、門檻、衰減包絡、最近一次力度、累積次數和峰時。可調低頻資料在 `impact`。八個固定頻段的 12 / 15 路舊特徵重播使用 55 ms 包絡差分後備路徑；低頻判斷始終使用恢復的逐次 log 能量差分。正式 Max patch 固定為 24 路，不靠該後備路徑。

**BODY** 由低頻持續量驅動，約 95 ms 上升、280 ms 釋放。它不等於低頻瞬態。

**PHRASE / BED** 分析 140–3500 Hz 子帶：相對頻譜形狀的變化、25 / 240 ms 振幅調制、既有中頻起音构成 articulation；共同增益變化可在頻譜比例中抵消。前景約 35 ms 上升、160 ms 下降。各子帶最近 60 幀（正常約 1.2 s）的第 22 百分位作持續底層，與當下能量比值形成 persistence；鋪陳約 400 ms 上升、240 ms 釋放。兩層都乘中頻能量，並非互補，允許重疊。

**DETAIL** 結合高頻短事件與少量高頻持續量。中／高起音合併各自子帶的 DSP 起音計數，最短間隔 100 / 65 ms，瞬態衰減 130 / 70 ms。

角色狀態由強度及其變化顯示休止、起音、延續、活動、退去。這是行為估計，沒有聲源分離或語義辨識。BPM 是約八秒 novelty 自相關資訊，有半拍／倍拍歧義；不控制視覺衝擊或原曲速度。

## 五層、六種空間構成

Renderer 圖層依序為 Impact / BODY / PHRASE / BED / DETAIL，每層有獨立拖尾與光量預算。低頻衝擊先以短促的局部亮起固定落拍，再呈現較暗的擴散尾部；亮度與衰減跟隨力度，擴散進度只跟隨事件年齡，避免力度補足時前沿倒退，取消把輕擊抬成同等強度的亮度下限。預算是各自上限，不是硬性先後分配。局部重疊另作能量壓縮，避免混成大片白色；整體還有光量上限。

沉積：底部面積、上行波前、歷史線、側邊鋪陳。公轉：月體、環狀衝擊、衛星前景、外環鋪陳。經緯：低頻支柱、縱向鋪陳、橫向前景、掃描衝擊。縱深：開放門框、方形衝擊、斜向深度節點。雙生：兩個不同低頻形體、交替前景、連結與双中心衝擊。碎片：2×2 拼塊、離散前景、斜向短擊。

前景和鋪陳有獨立能量積分時鐘。沒有输入時相應光層退暗，不繼續假造拍點。配色可獨立覆寫構圖預設，角色配色固定，無 hue cycling。

低頻事件到達即繪製，隨後重啟 33 ms 的殘影排程；其他事件保留計數，不会在兩幀之間丟失。Max 9 的 v8 執行分析／構圖，獨立 v8ui 接收 192 個 RGB 數值作快速預覽。文字介面約 125 ms 更新，經 deferlow 傳送 Dict 名稱；避免把每一幀的大型 JSON 字串轉成 Max symbol，並快取固定文字的字形路徑。凍結消耗過期事件，解凍不補播爆發；Pause 後重新 Play 同時清除分析與視覺事件基準，避免計數歸零導致新起音被忽略。音訊與殘影消失後 RGB 精確歸零。

GUI 與硬體使用同一 192 個整數 RGB（0–127）。GUI 有額外 gamma 顯示，螢幕比較不等於實體 LED 光度測量。

## 觸控與插件

觸點使用位置、velocity、aftertouch。單指滿壓 gesture strength 約 0.91，雙指達 1。預設 fxdepth 0.85，持續按壓的 amount = (0.25 + strength × 0.75) × depth × 0.95，實際 wet 上限 0.9、60 ms 平滑。

上下位置控制兩級低通 160–14160 Hz；右側且高壓時增加取樣保持（最多約 8 samples）與量化（最低約 7 bits）的數位顆粒。另有 310 / 430 ms 交叉延遲與四線阻尼回授空間。音訊乾濕交叉混合；無觸點時回到 dry，分析保持讀原音。Master 後 ±0.98 是保護，不是 mastering limiter。

`vst~` 要回報正數輸入／輸出且非 synth 才能啟用。提供原廠介面、preset 讀寫、bypass；開發時可發送 `pluginparam 編號 值`；未補償插件延遲。錄音先啟動 DSP 再開 float32 WAV，避免舊 sample-rate 標頭。

`sfplay~` 的停止 bang 與 EOF 以播放位置區分；Restart 直接 seek 到零，不發出延後 halt。一般進度 snapshot 每約 100 ms 更新。驗收另在繪製後請求播放器位置，從回覆 callback 寫入 trace，避免重入 JS 訊息延後而誤用上一幀位置；仍受音訊向量與系統排程影響，並非實體端到端延遲量測。

## Launchpad Pro MK3

依 [Novation Programmer Reference](https://fael-downloads-prod.focusrite.com/customer/prod/s3fs-public/downloads/LPP3_prog_ref_guide_200415.pdf) 實作。只選 LPProMK3 MIDI 端口，不選 DIN／DAW。

- Header：F0 00 20 29 02 0E。
- Programmer Mode：F0 00 20 29 02 0E 0E 01 F7。
- RGB 命令 03，每個 LED 條目為 03、index、red、green、blue，各色 0–127。
- 左下 pad 為 11；index = 11 + x + 10*y，x、y 為 0–7。
- 兩排底部按鍵為 CC 1–8 及 101–108；兩排對應同樣的獨看／低頻重量／還原功能。
- 接收 Note On、velocity 0、Note Off、poly aftertouch、channel pressure、running status；忽略穿插的 MIDI real-time bytes。
- 必須收到型號 inquiry 及 Programmer layout 17 才視為連線成功。型號 family byte 接受手冊的 19 和先前實機回覆的 35。
- 只送出改變的 LED，定期查詢 layout，失去回應會釋放觸點。按鍵保留選取狀態及約 180 ms 操作回饋。
- 歸還設備或關閉主 Patch 時關燈並返回 Live／Note layout。

## 維護、封裝與驗收

維護來源：`code/*.js`、`code/lens_fx.genexpr`、`scripts/controller-core.js`、`scripts/analysis-source.mjs`。`npm run build` 生成 99 個主物件、172 條連線及相鄰 bundle / Gen；關閉主 patch 後重建並重新載入。運行不依賴 Node 或 Python。

`npm test` 包含 71 組既有／調整後的結構、行為、事件、灰階構圖、配色、UI callback 及 MIDI／路由測試。另有 10,000 次低頻判斷與封存 1.1 完整引擎逐次比對，包含靈敏度、間隔及重設。這驗證回滾一致，不是音樂準確率。Native 全曲運行另見驗證紀錄.md。Callback 模擬不等於已用手操作 Launchpad。

`scripts/make-behaviour-fixture.py` 的已知訊號和 43 s 頻段更改是測試案例，從不載入演出引擎。`tmp/runtime-control.maxpat` 是本機驗收橋接，正式封裝不含 tmp 或自動網路接收器。`SHA256SUMS.json` 記錄封裝摘要。

後續評估需以真實混音片段人工標註重要衝擊與非衝擊干擾，涵蓋持續 Bass、失真、壓縮、低音人聲、段落切換及密集打擊；分開量測誤報、漏報和偏時，並保留未參與調參的曲目。合成訊號只作邊界與回歸測試。
