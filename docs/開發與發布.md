# 開發區、候選包與穩定版

穩定可用版固定為 **v1.4.1**。開發工作區在 `main` 持續迭代；`main` 的最新內容不等於正式版。正式版由 Git tag、GitHub Release ZIP 和 SHA256 一起識別，固定記錄在 `config/stable-release.json`。

## 本機入口

```text
~/Developer/
├── lunar-lens/                         開發工作區；唯一修改來源
│   ├── 開啟開發版.command             開啟本工作區的 Max Project
│   ├── lunar-lens.maxproj              開發版入口（生成檔）
│   ├── code/                          分層來源；分析 genexpr 有一個生成例外
│   ├── scripts/                       建置來源、控制器、驗收與版本工具
│   ├── patchers/                      生成的 Max 執行檔；不要直接修改
│   ├── config/stable-release.json     推薦穩定版的來源與固定雜湊
│   ├── tests/                         可重複的軟體回歸
│   ├── docs/                          工程設計、完整迭代史、已提交的驗證證據
│   ├── media/                         隨專案分發的 Demo 與展示素材
│   ├── dist/candidates/               未發布候選 ZIP（不進 Git／封裝）
│   ├── dist/reports/                  候選包的獨立驗證報告（不進 Git／封裝）
│   └── tmp/                           本機捕捉、研究素材、QA patch（不進 Git／封裝）
│
└── lunar-lens-releases/                穩定使用與歷史封存；不在此開發
    ├── 開啟穩定版.command             日常使用入口
    ├── current -> versions/v1.4.1/lunar-lens
    ├── versions/v1.4.1/
    │   ├── release.json               tag／commit／ZIP 雜湊安裝記錄
    │   └── lunar-lens/                原始正式 ZIP 完整解壓，檔案逐一核對
    ├── archives/v*/                   歷史 ZIP 與當時的 verification.json
    ├── ARCHIVE-INDEX.json              本機整理前後路徑、大小與 SHA256
    └── README.md
```

日常開 **`lunar-lens-releases/current/lunar-lens.maxproj`**，改程式才開 `lunar-lens/lunar-lens.maxproj`。兩個 `.command` 入口使用系統 `open -a Max`，不會先建置、下載或自動換版。

Max 專案內維持相對 `code/`、`patchers/`、`media/` 搜尋路徑，因此這次沒有搬動或改名執行模組。不要把整個 Developer 或 releases 加進 Max 全域搜尋路徑。切換版本前先停止並關閉另一個 Lunar Lens Project；兩版使用相同控制匯流排名稱及同一台 MIDI 設備，不能以同時開啟作為隔離比較。

## 哪裡可以修改

| 內容 | 修改位置 | 後續動作 |
| --- | --- | --- |
| 測量、行為、事件、呈現、互動、協定、UI | `code/` 對應模組 | build → test |
| 低頻／八頻段分析 DSP | `scripts/analysis-source.mjs` | build 產生 `code/lens_analysis.genexpr` |
| 控制器時鐘、檔案／MIDI／音訊路由 | `scripts/controller-core.js` | build 合併成 `patchers/lens_runtime.js` |
| Max 物件與接線、Project 內容 | `scripts/build.mjs` | build 產生 `patchers/` 與 `.maxproj` |
| 已驗證正式版 | 不直接修改 `versions/` | 在開發區修改，通過新版本發布流程 |

生成檔繼續進 Git，讓下載原始碼仍能直接用 Max 開啟，也能在 diff 中檢查接線變化。`.maxproj` 與 `patchers/` 不是第二份來源。穩定版保留正式 ZIP 的完整原始內容，包括其當時的來源與文件，以便還原；它不是第二個開發工作區。

`tmp/` 現有原始錄音、特徵與實驗沒有刪除或重新搬動，避免破壞歷史驗證腳本。新的候選 ZIP 統一寫進 `dist/`，有價值的驗證摘要再選擇性提交到 `docs/`；參考歌曲不進 GitHub。

## 開發與候選驗證

在 `lunar-lens/` 執行：

```sh
npm run build
npm test
npm run package
npm run verify:package
npm run stable:verify
```

`build` 只更新本 checkout 的生成檔；開著開發版時，autowatch 可能重新初始化當次狀態。穩定版放在獨立的 releases 目錄，不會被這個建置寫入。

`package` 每次產生獨立的 `lunar-lens-v…-candidate-時間-識別碼.zip`，也產生同名 JSON 與 `latest.json`。即使 package.json 仍是 1.4.1，也只表示以此版本為基礎的候選包，**不是新的 v1.4.1 正式包**。指令沒有任何更新穩定版指標、改 tag 或上傳 GitHub 的動作。

`verify:package` 核對 ZIP 與所有檔案雜湊，在系統暫存目錄解壓、重建、執行全部軟體測試，並要求 Max 生成檔重建後一致。`dist/reports/` 保留每個 ZIP 的同名驗證 JSON，`release-verification.json` 另記錄最後一次結果。也可指定某個歷史 ZIP：

```sh
npm run verify:package -- /完整路徑/候選包.zip
```

純封裝與文件改動採用軟體／檔案驗證。涉及音訊、視覺或互動的改動，仍須補上對應的 Max 原生播放／操作證據；軟體測試不能取代主觀聆聽、實曲誤報標註或實體 Launchpad 驗收。

## 穩定版安裝與切換

初次整理已完成 v1.4.1 安裝。其他電腦先下載 `config/stable-release.json` 中 releaseUrl 頁面的同名 ZIP，再執行：

```sh
npm run stable:install -- --archive /完整路徑/lunar-lens-v1.4.1.zip
npm run stable:status
npm run open:stable
```

安裝只接受固定雜湊和版本相符的 ZIP。原始包存入 `archives/<tag>/`，逐檔驗證後解壓到 `versions/<tag>/`，最後切換 `current`。同版本已安裝時先核對；檔案改動、不同包或真正的 current 資料夾都會阻止覆寫。`stable:verify` 檢查原始 ZIP 與所有已分發檔案；若在 Max 中另存改過它，先把改動另行保留，再由開發區處理，不以重裝悄悄蓋掉。

選回**已安裝**的版本：

```sh
npm run stable:use -- --version v1.4.1
```

此動作只切換 `current` 捷徑，不會刪除另一版本。只有放在 archives 的早期 ZIP 不代表已安裝。需要其他存放位置時，以上 stable 指令都可加 `--store /完整路徑/獨立目錄`；該目錄不可是開發工作區、其子目錄或其父目錄。

## Git 與正式發布規則

| 名稱 | 意義 |
| --- | --- |
| `main` | 開發整合分支；文件、工程整理與通過回歸的迭代在此同步 |
| `feature/*` | 需要較長時間比較的實驗；完成後再合併 main |
| `vX.Y.Z` tag + GitHub Release | 已發布的固定版本；既有 tag 和 ZIP 不覆寫 |
| `config/stable-release.json` | 經驗收後推薦日常使用的正式版本，不跟著 main 自動升級 |

不另設一個會移動、卻名叫 stable 的來源分支。已發布 tag 和獨立安裝內容才是可回到的穩定基線。

下一次發布順序：先在開發區更新版本號、迭代紀錄與證據 → 建置及軟體／必要原生驗收 → 封裝並獨立驗證 → 在對應提交建立新 tag 和 Release、上傳已驗證的包 → 核對遠端資產 SHA256 → 更新 stable-release.json → 安裝並切換。候選包升為正式資產時可以改檔名，不能在驗證後再改包內內容。這次只整理工作流程，**沒有發布新音訊／視覺版本，穩定版仍是 v1.4.1**。

完整歷史繼續記錄在 [迭代紀錄](迭代紀錄.md)。原來的 Lunar Departure 是另一個保留的演奏專案，此次不搬動它。
