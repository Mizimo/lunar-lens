# 驗證紀錄 · 1.0.0

2026-09-09，macOS / Max 9.1.4 arm64。已收斂為可直接運行的 Max Project。以下區分原生 Max 實測、模型／結構檢查及仍需實體觀察的部分。

## 完成與修正

- 八頻段分析、三組獨立起音、四個視覺角色；五種構圖都保留低頻本體。
- 低頻面積與衝擊位移取代微小軌道變化；高頻使用短消退，保留暗部。
- 新增逐層獨看、低頻重量、恢復預設，以及兩排底部控制鍵的選取／短暫操作燈。
- 修正短事件在兩個渲染幀之間結束後被漏掉的情況。
- 修正中頻和弦的濾波殘留誤觸低頻，以及靜音後由舊歷史重新鎖定 BPM。
- 原生操作驗收發現 sfplay~ 的停止 bang 可在快速 Restart 後誤判為 EOF；已改為直接 seek 到零，並檢查完成位置。修正後重新載入 Max，重跑操作驗收與整首 Sana。

## 自動檢查

npm test 通過 **45 組**：31 組控制器／接線／播放器／協定檢查，14 組分層驗收。主 Patch 有 83 個物件、130 條接線。另檢查相鄰 bundle、十二個同步 snapshot、效果前分析、監聽與錄音路由、空插件防護、EOF／Restart、MIDI running status、壓力與釋放、連線握手、兩排底部 CC 別名、低頻面積、灰階結構區別、獨立拖尾、靜音全黑。

這些測試證明可重現的行為與工程約束，不能代替人耳和實際房間中的燈光感受。

## 指定 Sana 整曲

實際載入「ハッピーでバッドな眠りは浅い - Sana.mp3」，Max 讀到 44.1 kHz、立體聲、**197.044535 秒**。所有視覺參數使用預設，不讀取歌名或歌曲時間提示；播放為原速 1×。

最終程式完成整首與曲尾退暗驗收，全部幀的監聽為 OFF、RGB 為合法整數，沒有卡在播放狀態。最終捕捉 6,056 幀，平均間隔約 33.04 ms、99 百分位約 34 ms，播放中的最長間隔約 52 ms。曲尾已停止後操作 Console 時出現一次約 216 ms 的間隔，完整數據保留，沒有把它刪除。逐幀統計、四角色分布和最終生成檔案 SHA-256 見 sana-full-validation.json。角色相關度只作「是否一起跳動」的參考，不能當成鼓／貝斯／人聲分離準確率。

另外錄製約 39.8 秒原生乾音輸出，與原始 MP3 經 ffmpeg 解碼的同位置對齊：增益約 0.3981、相關度約 0.99958、峰值約 −7.96 dBFS。Max 與 ffmpeg 的 MP3 解碼／採樣率轉換有差異，不宣稱 bit-perfect。比較見 sana-audio-validation.json。

此曲原始 MP3 不隨封裝分發；靜態預覽只保留分析後的 LED 幀。

## 互動、播放器與效果器

修正版 Max 主程式用與滑鼠／硬體共用的 pad、pressure、padup、CC、transport 處理函數完成驗收；這部分是本機命令注入，不是實體手指測試。

- 輕壓／全壓／雙觸點／放開：效果強度約 0.108 → 0.500 → 0.943 → 0。
- 相對乾音誤差：未按約 0.00695，按住約 0.24124，放開後約 0.00374；效果確實加入並回到乾音附近。
- 原生觸控錄音約 10.44 秒，峰值約 −22.77 dBFS；全部有限值。
- Pause 在位置 snapshot 穩定後不再前進；seek 至 25% 後繼續；Restart 回零播放；Stop 位置歸零並清空畫面。
- Blackout 在持續音訊與觸點下仍全黑；凍結背景仍有觸點回饋；獨看、低頻重量與還原依預期更新，還原保留播放與 Master。
- 本機 **FabFilter Pro-R 2 VST3** 成功回報效果器輸入／輸出、啟用並完成約 4.02 秒實錄，峰值約 −24.32 dBFS；最後回到 BYPASS。

資料見 session-validation.json。media/touch-feedback-demo.mp3 是本輪觸控效果錄音。未逐一測試所有本機插件；AU 支援沿用 Max vst~，本輪沒有個別 AU 實錄。

## 視覺與硬體邊界

已在 Max 主視窗觀察實際 Sana 播放的四層畫面、中文排版、控制區和原生 MIDI 選單；另檢視靜態對照圖及 16 秒動態驗收影片。影片使用原創已知測試訊號，大圖為 Max 實際 RGB，小圖為相同特徵經正式渲染器的獨看結果。影片的時間標籤是驗收註解，不進入產品的視覺演算法。

本輪完成時 USB／Max MIDI 列舉**沒有 Launchpad Pro MK3**，因此不能宣稱新版已完成實體按鍵與 LED 視覺驗收。協定、8×8 映射及兩排底部 CC 已依官方 Programmer Reference 核對。0.1 時曾實際收到型號 inquiry 和 Programmer layout 17；那份歷史證據保留在 archive-v0.1，不冒充新版實機驗收。

滑鼠自動注入未能可靠觸發 Max JSUI，且切換前景的工具逾時；直接呼叫 JSUI 的 onclick 可正常送出播放命令。因此介面已作視覺檢視和回呼驗證，但不宣稱已完成人工滑鼠實測。診斷程式已移除，執行檔案與整曲驗收的 SHA-256 相符，測試 UDP 視窗已關閉，7474 端口已釋放。

沒有開啟喇叭作人耳主觀試聽；錄音量測證明訊號、效果與釋放行為。尚未量測真實音訊起音至實體 LED 的端到端延遲，也未在不同房間校準暗部亮度。

## 可攜性與重跑

完整封裝包含 Max 執行檔案、維護來源、Demo、說明與驗收報告，不包含原曲 MP3、開發 tmp 或測試 UDP 橋接。npm run package 生成每檔案 SHA-256 並重新讀取 ZIP 驗證；解壓後可直接用 Max 開啟。

重跑主要工程檢查：npm test。重跑原生訊號需先 npm run build，再開主 Patch 與 tmp/runtime-control.maxpat，依序執行 make-role-fixture.py、native-acceptance.py、verify-native-roles.py。操作驗收為 run-session-checks.py、verify-session.py；指定音檔整曲為 run-song-check.py 加完整路徑，再執行 verify-song-trace.py。音訊驗收需要 Python／numpy／ffmpeg；一般使用只需 Max。
