# 工程設計 · 1.0.0

## 設計原則

每首錄音和即時輸入使用同一套分析、事件與構圖。分析器和渲染器不接收曲名、歌詞、歌曲長度、小節或人工提示點；進度只用於播放器。Demo 只呼叫一般音檔載入。驗收用的已知訊號標籤僅存在測試腳本，不是演出控制資料。

聲音仍是原始錄音，以 1× 速度播放。沒有重新合成原曲、swing、量化或根據 BPM 拉伸音訊。這個專案與保留的 Lunar Departure 音序演奏系統各自獨立。

## 訊號路徑

    sfplay~ / adc~ → 來源選擇 ┬→ gen~ lens_analysis → 12 個同步 snapshot
                             │                       ↓ LensFeatures
                             │                       ↓ LensVisual ← MIDI／滑鼠
                             │                         ├→ JSUI 預覽
                             │                         └→ Pro MK3 RGB SysEx
                             └→ gen~ lens_fx → 可選 vst~ → Master → ±0.98 保護
                                                                    ├→ sfrecord~
                                                                    └→ 監聽開關 → dac~

分析讀取效果器和 Master 之前的立體聲輸入。觸控改變效果，不會製造回授式假起音。關閉監聽仍可分析和錄音。

## 音訊分析

scripts/analysis-source.mjs 是分頻器的維護來源，生成 Gen codebox。左右聲道各自經 DC block 及八個交疊四階帶通，每個頻段由兩個 RBJ constant-peak-gain biquad 串聯。係數依實際 sample rate 計算。頻帶名義邊界為 30–70、70–140、140–280、280–600、600–1500、1500–3500、3500–7500、7500–16000 Hz；這些不是互不重疊的磚牆濾波。

左右功率平均後，以約 8 ms 指數包絡得到各頻段 RMS，避免先相加為 mono 造成反相抵消。其餘四個輸出為總 RMS、peak、mono RMS、side RMS，共 12 值。qmetro 20 以 trigger 先更新 pack 的冷入口，最後才輸出完整分析幀。

LensFeatures 將八頻段形成三組頻域角色，分別維護正向 log-energy 變化、適應門檻、起音計數和包絡。三組的最短起音間隔為 120／100／65 ms，瞬態衰減為 180／130／70 ms。持續低音另有約 95 ms 上升、280 ms 釋放，不以同一條包絡同時表示鼓擊和延音。

音量參考有下限；安靜時不把底噪一路放大。各組相對總 RMS 的佔比用來抑制濾波器裙邊殘留。原生驗收曾發現中頻短和弦誤觸低頻，加入佔比判斷後，移除低頻的測試中衝擊和低音接近零。這個判斷不是樂器識別，也不能保證底鼓／貝斯完全獨立。

中頻輪廓來自頻帶比例與短歷史，不是旋律音高。立體聲寬度來自 Mid／Side。BPM 使用最多約八秒 novelty 的自相關估計，有半拍／倍拍歧義；只顯示資訊，不控制播放速度，也不代替低頻實際事件。靜音時不從舊節奏歷史重新鎖定。

## 四層視覺

| 角色 | 幾何與動態 | 留白策略 |
| --- | --- | --- |
| 衝擊 | 真實低頻起音推動上升波前、擴張輪廓或菱形傳播 | 約半秒內消失，不用全屏白閃 |
| 低音 | 下方連續形體，能量改變面積、寬度與厚度 | 所有構圖保留本體，高頻不能擠掉它的光量 |
| 中頻 | 中上方連續線，輪廓、強度與起音各自變化 | 與低音在位置、形狀和時間上分開 |
| 高頻 | 上方／邊緣的少量短點和兩個微弱延續亮點 | 獨立快速消退，長殘影也不拖成低頻形體 |

五個構圖為重力、天體、潮汐、折線、極簡；只改構圖，角色職責不變。每層有獨立歷史與光量上限，總光量先保留低頻，再容納細節。1.0 沒有舊版的自動場景權重切換。

渲染約每 33 ms 一幀。分析起音以單調計數交付，短事件即使在兩幀之間結束，仍會生成一次視覺回應。凍結時消耗事件計數，不在解除時補播整串過期衝擊。靜音和拖尾結束後 RGB 精確歸零。

GUI 和硬體使用同一個 192 整數 RGB 陣列，範圍 0–127。GUI 額外做顯示 gamma；截圖不能充當實體 LED 光度測量。

## 互動與音訊效果

每個觸點帶有位置、按下力度與壓力。按下立即請求渲染，局部暖光和短波紋回應；持續按住移動形體重心與細節吸引點。放開取消吸引力。凍結保留背景，仍容許手勢回饋；Blackout 覆蓋背景、手勢和全部硬體邊框。

觸控聲音效果預設可用，只有按住才加入。高度控制濾色，左右位置控制空間衰減，力度／壓力控制送出量。原生效果包含 310／430 ms 交叉延遲及四線阻尼回授空間，效果量以 80 ms 平滑；無觸點時回到 dry。Master 後的 ±0.98 ceiling 是保護，不是 mastering limiter。

vst~ 為可選音訊效果匯流排。必須回報正數輸入／輸出且不是 synth，才允許啟用；空插件不會切斷原音。插件介面可選 preset 及參數，也提供 read／write／bypass。第三方插件的延遲不補償到視覺；分析維持效果前時間。

錄音先啟動 DSP，再開 WAV、開始寫入，避免沿用舊 sample rate 標頭。檔案為監聽前、Master 後的 float32 立體聲。

播放器對 sfplay~ 的停止 bang 和真正 EOF 作區分。Restart 直接 seek 到零，避免 stop／start 的延後停止通知中斷新播放；EOF 另外核對接近曲尾的位置。Pause 後進度 snapshot 最多約一個更新週期才顯示最終位置。

## Launchpad Pro MK3

依 [Novation Programmer Reference](https://fael-downloads-prod.focusrite.com/customer/prod/s3fs-public/downloads/LPP3_prog_ref_guide_200415.pdf) 實作。只選 LPProMK3 MIDI 端口，不選 DIN／DAW。

- Header：F0 00 20 29 02 0E。
- Programmer Mode：F0 00 20 29 02 0E 0E 01 F7。
- RGB 命令 03，每個 LED 條目為 03、index、red、green、blue，各色 0–127。
- 左下 pad 為 11；index = 11 + x + 10*y，x、y 為 0–7。
- 兩排底部按鍵為 CC 1–8 及 101–108；兩排對應同樣的獨看／低頻重量／還原功能。
- 接收 Note On、velocity 0、Note Off、poly aftertouch、channel pressure、running status；忽略穿插的 MIDI real-time bytes。
- 必須收到型號 inquiry 及 Programmer layout 17 才視為連線成功。型號 family byte 接受手冊的 19 和先前實機回覆的 35。
- 只送出改變的 LED，定期查詢 layout，失去回應會釋放觸點。按鍵保留選取狀態及約 180 ms 操作回饋。
- 歸還設備或關閉主 Patch 時關燈並返回 Live／Note layout。

## 原始碼、封裝與邊界

修改 code/、scripts/controller-core.js、scripts/analysis-source.mjs 後，用 npm run build 生成相鄰 JS bundle、Gen DSP 和主 Patch。先關閉主 Patch，再重建、重新開啟。正常運行不需要 Node、Python 或額外 Max 套件。

tmp/runtime-control.maxpat 是本機驗收用 UDP 7474 橋接，正式封裝不包含 tmp，也不自行啟動接收器。scripts/ 中的音訊／視覺驗收不是產品中的逐曲例外。SHA256SUMS.json 記錄封裝內檔案摘要。

1.0 不宣稱理解歌詞、辨識樂器或分離人聲。若下一輪要從「聲音角色」提高到可確認的鼓／貝斯／人聲，最值得加入的是對每首音檔相同的自動分軌分析，再以已知 stems 交叉驗收；原始錄音仍可保持不變。即時輸入必須另外評估模型延遲與成本。

## 研究來源與採用範圍

[AudioLink](https://github.com/llealloo/audiolink/blob/master/Docs/README.md) 啟發多時間尺度、歷史和空間傳播；[MilkDrop](https://www.geisswerks.com/hosted/milkdrop2/milkdrop_preset_authoring.html) 與 [Butterchurn](https://github.com/jberg/butterchurn/blob/master/src/audio/audioLevels.js) 提供瞬間／持續量分離和每頻段參考的思路；[WLED](https://github.com/wled/WLED/blob/main/usermods/audioreactive/audio_reactive.cpp) 提供有限 LED 的能量包絡參考。本專案實作自己的 Max 分頻、事件和幾何，未複製這些渲染器。

也調查 [FluCoMa HPSS](https://learn.flucoma.org/reference/hpss/) 及 [Demucs](https://github.com/facebookresearch/demucs)。它們未被整合進 1.0，不能把本版四層稱為 HPSS 或 AI stems。Lineform 的音訊特徵與幾何控制研究保留於視覺分層研究.md。
