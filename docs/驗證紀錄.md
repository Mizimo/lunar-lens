# 驗證紀錄 · 1.2.1 低頻回滾

2026-09-09 · Max 9.1.4。使用者在《Blossoms》的真實混音中確認 1.2 低頻誤觸增加，因此將低頻事件判斷恢復為封存 1.1 的完整規則。1.2 合成鼓點的 42/42 與軟體時間數字，不構成真實編曲的準確率證據；舊報告與否決原因保存在 archive-v1.2。

## 回滾內容與保留範圍

恢復能量比 > 1.35、原先逐次 log 包絡起音量、75 次讀值的平均／標準差門檻、ratio < 1.025 的重新準備條件，以及原本最短間隔。原始 1.1 引擎在 tests/reference/lens_features-v1.1.cjs，只供測試使用；生產程式不讀測試檔案或曲名。

已接受事件的連續力度、最快光幀輸出、文字與網格分離、八段独立動態、六構圖／配色、觸控效果與 MIDI 協定保留。Renderer、Grid、Protocol、FX、DSP 生成器和 Gen 輸出已與 1.2 ZIP 逐位元組比對相同；詳細範圍在 rollback-scope-validation.json。已保存的使用者 patch 位於本機 tmp/user-patch-before-rollback.maxpat，接線端點與 1.2 相同，差異為 Max 序列化、端口清單和介面狀態。

## 正確性檢查

71 組既有／調整後軟體測試通過；新增的低頻回滾測試對照封存 1.1 引擎 10,000 次判斷，涵蓋靈敏度、最短間隔、重設及不同更新間隔，事件、上升量與門檻逐次一致。原先要求低於 1.35 能量比仍接受低頻脈衝的測試，已按回滾規格改成能量比不能被短峰繞過；小重音與密度切換測試仍保留給八個固定頻段。歷史 1.2 的合成低頻驗收目標不再作新版放行標準。

從真實《Blossoms》錄音封存的 5849 個特徵更新，送入 1.1、1.2 及回滾版。回滾版低頻事件與門檻對 1.1 的差異均為 0；八段 bandDynamics 與中／高頻事件對 1.2 也完全一致。詳見 low-rollback-validation.json。

這是同資料的程式行為對照。特徵捕捉在畫面更新時取樣，沒有包含每一次原生分析；不能把重播事件數當成原始原生事件數，也不能以事件減少推導誤觸減少。

## Max 全曲運行

主 patch 重新載入，使用相同預設 35–160 Hz、靈敏度 1、最短間隔 160 ms，在 Max 原速完整播放《Blossoms Bring an Old Friend》193.316 秒。收集 6008 幀，平均更新間隔 32.68 ms、P99 52.00 ms、最大 63.00 ms。播放結束停止、黑屏，192 路 RGB 均為合法整數。音訊監聽在測試期間關閉。詳見 blossomsrollback-full-validation.json，包含執行檔案 SHA-256。

本輪没有人工逐拍標註，沒有宣稱底鼓 precision／recall 或實體 LED 延遲已達標。聲音輸出、VST 及其他操作路徑沒有更改，先前測試只作歷史參考。

## 後續驗收方式

先用真實混音片段人工標註重要衝擊、非衝擊干擾、輕重與可接受偏時；涵蓋密集低音、壓縮、失真、低音人聲與段落轉換。分開計算誤報、漏報及偏時，另留未參與調參的曲目。合成訊號只作邊界與回歸測試。所有曲目共用同一套生產邏輯。

## 重現與封裝

關閉主 patch → npm run build → npm test → 重新載入。混音特徵對照：node scripts/verify-low-rollback.cjs 特徵JSONL 1.2引擎檔案。全曲運行：開啟 tmp/runtime-control.maxpat 後，python3 scripts/run-song-check.py 音檔路徑 blossomsrollback → python3 scripts/verify-song-trace.py blossomsrollback。

npm run package 產生 1.2.1 獨立 ZIP；python3 scripts/verify-release.py 驗證封裝、在專案外解開重建、測試及比對生成內容。tmp 與原始參考曲不收進封裝，先前 ZIP 保留。
