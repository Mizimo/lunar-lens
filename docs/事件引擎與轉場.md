# 1.3 音頻引擎、事件與轉場

本輪從使用者接受的 1.2.1 低頻回滾版出發。新的結構判斷獨立運作，不能替低頻 IMPACT 補拍，也不改變原曲速度。所有曲目走同一組規則。

## 研究依據

- [iZotope：Ozone Master Assistant](https://www.izotope.com/community/blog/how-to-use-master-assistant-in-ozone)：參考其分別處理 tone、dynamics、width、loudness 的觀念。商用系統的人聲處理與學習模型不等於本專案已具有相同能力。
- [FluCoMa SpectralShape](https://learn.flucoma.org/reference/spectralshape/)：頻譜重心、展寬、平坦度等描述量可以區分音色，但每一項都只描述聲音的一部分。本專案自行實作立體聲功率頻譜測量，不依賴 FluCoMa 安裝，也未複製它的實作。
- [FluCoMa NoveltySlice](https://learn.flucoma.org/reference/noveltyslice/)：把「較長時間尺度上的變化」與短促起音分開。本版採因果的近期／背景對照，並非完整的自相似矩陣分段演算法。
- [Lineform getAdvancedAudioInfo](https://github.com/Mizimo/Lineform-See-the-music/blob/main/src/lib/getAdvancedAudioInfo.js)：讀過實際原始碼，這個函式提供音檔基本資料、峰值、RMS 與峰均比，而且讀的是第一聲道。本版保留這類可解釋測量的優點，改為即時、立體聲、分時間尺度的輸出；沒有把它描述成歌曲結構辨識模型。
- [Cycling '74 pfft~](https://docs.cycling74.com/reference/pfft~/)：原生 STFT 管理。`fftin~` 的左右聲道功率合成後，交給 Gen 計算描述量，再由 `out 1` 輸出完整列表。

## 測量契約

`LensMeasurements` 輸出 `schemaVersion: 1`，不包含顏色、場景或 MIDI。

| 群組 | 值與單位 | 用途／界線 |
| --- | --- | --- |
| spectrum | centroidHz、spreadHz | 功率加權頻譜重心與標準差，並不是音高 |
| spectrum | flatness、entropy、concentration | 平坦度、正規化頻譜熵、最大頻格功率占比；不是樂器分類 |
| spectrum | change | 相鄰 FFT 功率向量的 cosine distance；整體乘同一個增益時不變 |
| level | rmsFast、momentaryDb、shortTermDb、crestDb | 原始快速 RMS、0.4／3 秒時間常數的 RMS dBFS、峰均比；不是 BS.1770 LUFS |
| space | correlation、balance、sideRatio | 左右相關度、左右功率偏移、Side 比例；相關度保留負值 |
| waveform | zeroCrossingRate | 每個取樣點的平均過零比例；高值不等於人聲或噪音分類 |
| bandPowerShape | 8 個比例 | 原有濾波器組的功率分布，供較慢的結構對照 |

FFT 使用 2048 點、4 倍重疊，hop 512。頻率換算採 **實際 DSP 取樣率**，不以音檔取樣率代替。左右複數頻譜分別轉功率後相加，反相立體聲不會因先加成 mono 而消失。DC 不參與形狀計算。

描述量在完整頻譜結束時一起鎖存；頻格序號不再更新超過 180 ms，便標記 `valid: false`。頻譜分析有一個窗長附近的延遲，不用它推遲原有低頻起音。所有測量都在觸控效果、插件及 Master 之前。

## 事件契約

`LensEvents` 消費測量與行為估計，輸出 `state`、最近 2 秒的 `events`、累計 `totals`。每個事件有：

```json
{
  "id": "4:19",
  "type": "structure.change",
  "time": 123.45,
  "observedTime": 122.99,
  "strength": 0.64,
  "confidence": 0.67,
  "evidence": {
    "shapeDistance": 0.28,
    "textureDistance": 0.12,
    "widthDistance": 0.1,
    "levelDifferenceDb": 1.6
  }
}
```

`time` 是傳入引擎的秒時鐘；Max 轉接器目前使用牆鐘秒數。檔案播放位置另外存在捕捉紀錄的 `position`。`observedTime` 記錄結構候選開始的時刻；`time` 是完成確認、發出事件的時刻。這樣可以區別回溯估計與真正的因果延遲。

`confidence` 是可解釋條件組合的啟發式分數，**不是校準過的機率**。不同事件的信心分數不能當分類器準確率比較。

| 事件 | 判斷 | 呈現 |
| --- | --- | --- |
| onset | 原有低頻探針或各頻帶局部起音；保留輕重 | IMPACT、前景短動作、細節點 |
| role.enter / role.exit | PHRASE／BED 通過上下不同門檻並維持一段時間 | 前景進入、光幕退去；事件頁可見 |
| sound.enter / sound.exit | 可聽活動進入／安靜持續 | 顯示進入／消失；退場抑制背景 |
| texture.change | FFT 形狀與頻譜分散度同時改變 | 細節的短促質感變化 |
| dynamics.rise / dynamics.fall | 0.4／3 秒能量差持續約 650 ms，初始暖機後才判斷 | 地基份量、鋪陳退去 |
| structure.change | 音域分布變化，加上音色／寬度／能量至少一個支持條件，持續 450 ms | 空間重新展開、鋪陳留下窄幅暗縫，之後恢復 |

結構候選有 4 秒最短間隔。單一增益變化不能通過結構條件。確認候選期間暫停背景參考追趕，避免邊觀察邊抬高參考。它仍可能把明顯配器／和聲變化當成結構事件，或漏掉聲學差異很小的段落：介面因此標示「候選」，不標主歌、副歌、歌詞段落或歌曲身分。

起音密度把 85 ms 內的跨頻段起音合併計數，再觀察 2 秒窗口；這不是 BPM。事件流保留 ID，呈現層只消費一次，同一筆資料被 30 fps 重播也不會反覆觸發。

## 五個行為的設定

左側「調」或右側行為頁選擇 IMPACT／BODY／PHRASE／BED／DETAIL。每個行為保存自己的響應、視覺份量、形體寬度與延續倍數，切換構圖不會丟失。

- IMPACT 的響應直接調整原有低頻探針靈敏度；下方有連續 Hz 範圍和重觸間隔。1.35 能量比與原起音門檻始終有效。
- 其他四個行為的分析音域，從八個**重疊頻帶**中複選。這是粗音域遮罩，並非任意 Hz 的精密濾波器。預設音域完整保留原有行為估計。
- 自訂音域會以所選頻帶重新觀察包絡、形狀活動、持續底層及各頻段起音。因此高音域也可以用來做 BODY，持續低音也可以成為 BED。頻域仍不是聲部標籤。
- 改變音域後，新增的自訂起音有約 300 ms 暖機；不會修改測量資料、播放 EQ 或其他行為的設定。
- 形體寬度改變該層水平方向的空間尺度；延續倍數改變該層殘影，並不延長原音。
- 響應作用於分析／行為估計；視覺份量只改燈光。歸零視覺份量可靜音一層燈光，同時保留事件監看。

## 轉場與交互

構圖、配色或獨看切換，會對背景層做線性光混合，依目標構圖使用徑向、斜向或垂直展開。預設 0.85 秒，可調 0–3 秒，0 即硬切。

快速連續切換，從當前正在顯示的混合畫面重新出發。IMPACT 與觸控光位於混合後的即時層，不會等轉場完成；Blackout 最後覆蓋所有輸出並清空轉場來源。凍結可保留背景，觸控仍可回應。

`LensInteraction` 擁有按壓、壓力和釋放狀態。視覺與聲音效果分別讀取它，不再由繪圖器負責解釋硬體 MIDI。`LensPresentation` 把事件轉成有限生命的視覺狀態；`LensVisual` 只處理空間與顏色；`LensTransition` 只混合背景。

## 驗證方式

測量校準使用已知訊號檢查單位、左右相關與反相保留，作用僅限測量正確性。事件的軟體測試檢查狀態邏輯、重播、暖機、上下文變化、轉場中再次切換和 Blackout。

真實音樂另以使用者指定的《Blossoms》和《ヰ世界の宝石譚》原速運行、輸出事件時間線與信心分數。沒有逐事件人工標註，因此不計算也不宣稱 kick／段落識別的 precision、recall。下一步應收集跨曲目標註，包含密集混音、慢漸強、強 Bass、小重音、短填奏、停頓與弱結構變化，將調整曲和保留驗證曲分開。
