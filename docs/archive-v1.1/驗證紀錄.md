# 驗證紀錄 · 1.1.0

2026-09-09 · macOS · Max 9.1.4 arm64。主 patch 重新載入後完成下列驗收。記錄區分原生 DSP、可重現軟體檢查及主觀／實機邊界。

## 自動檢查

`npm test` 通過 **56 組**（31 組工程與控制、14 組頻域分層、11 組行為與新控制）。主 patch：**86 個物件、139 條連線、15 個同步分析輸出**。

檢查包含沉默不生事件、噪底、已知脈衝、慢漸強、頻段外殘留、最短間隔、上下限不交叉、調頻冷卻、兩層共存、六模式固定配色下的灰階區別、配色不改幾何、五層獨看、有限 RGB、凍結、Blackout、壓力、MIDI 握手與 running status、控制器及 JSUI 兩個面板回呼。

另修正 Pause 後 Play 清零分析事件卻保留舊視覺計數，導致前幾次新起音被忽略的問題。恢復播放時兩側一併重置。

## 原生行為與頻段控制

`scripts/make-behaviour-fixture.py` 生成 56 秒原創訊號，經實際 `sfplay~ → gen~ → LensFeatures → LensVisual` 分析及 `sfrecord~` 錄音，非模擬 DSP。

| 相同音域的訊號 | 前景平均 | 鋪陳平均 |
| --- | ---: | ---: |
| 穩定 440 / 660 / 1100 Hz 延音 | 0.074 | 0.650 |
| 同音域音節式短音 | 0.552 | 0.002 |
| 延音與短音疊加 | 0.485 | 0.441 |

疊加區域約 95.3% 的捕捉幀中，兩層同時高於 0.2。這只驗證行為差異與共存，不能當作真實人聲／Pad 分離準確率。

Impact 初測發現：兩次緩慢低音漸強、六次 300 Hz 帶外短音會誤觸。收緊上升速度下限及頻段佔比後，以相同輸入重跑：

- 8 次 85 Hz 短擊：**8 次觸發**。
- 慢低音漸強：**0 次誤觸**，BODY 平均仍有 0.603。
- 預設 35–160 Hz，6 次 300 Hz 短擊：**0 次觸發**。
- 上限改為 380 Hz，同樣 6 次 300 Hz 短擊：**6 次觸發**。
- 結尾靜音：RGB 全黑。

頻段切換只存在於驗收腳本；播放器和 Renderer 不讀取這些測試時間。對齊輸出後，原音增益 0.400000、相關度 1.000000，訊號有限、無削波。見 `behaviour-validation.json` 與 `media/behaviour-comparison.png`。

## 原生頻域與路由回歸

原有 45 秒頻域測試以新版重跑。低／中／高測試分別落在預期頻帶；反相輸入保留能量、同相寬度接近零；120 BPM 脈衝建立節奏信心；移除低頻後 Impact / BODY 退下，中頻短音仍有前景。950 Hz 長音的起音先形成前景，5.8–6.25 s 穩定段前景約 0.008、鋪陳約 0.689，符合攻擊轉延續的設計。

錄音 48 kHz / 46.315 s，增益約 0.400000、對齊相關度 1.000000、峰值 -15.84 dBFS。見 `native-role-validation.json`。

## Sana 整曲

指定音檔 `ハッピーでバッドな眠りは浅い - Sana.mp3`：**197.044535 s**、原速 1×、44.1 kHz 立體聲。使用預設分析／視覺參數，沒有曲目例外。捕捉 **6063 幀**，平均 **33.00 ms**，P99 **35.0 ms**，最長播放幀距 **96.0 ms**。曲尾停止、192 個 RGB 歸零。

前景與鋪陳相關係數約 0.158，低頻 Impact 與 BODY 約 0.283；只描述包絡是否一起起伏，不能當成分軌品質分數。事件數 [192, 546, 726] 也不是拍子正確率；此商業錄音沒有人工標註真實 Impact。

原始 MP3 不隨封裝分發。`sana-full-validation.json` 含完整統計及本輪原生實測的五個生成執行檔 SHA-256。

驗收腳本以監聽 OFF 開始；紀錄顯示行為測試約 21.56–25.26 s、Sana 約 61.87 s 以後監聽曾切為 ON。因此不宣稱所有測試全程靜音。這個開關位於分析與錄音之後，不影響上述特徵和音訊比對。操作驗收則全程 OFF。

## 觸控、播放器與插件

經與滑鼠／硬體共用的 `pad / pressure / padup / CC` 處理函式注入本機命令並實錄：

- 輕壓 → 全壓 → 雙指 → 釋放：gesture strength **0.197 → 0.909 → 1.000 → 0**。
- 相對乾音差異：未按 **0.0242**、按住 **0.4475**、釋放後 **0.0141**。同測法的 v1.0 按住值 0.2412；新版約 **1.86 倍訊號差異**，不是「響度增加幾倍」。
- 錄音 **10.432 s**，峰值 **-22.78 dBFS**，全數有限。乾音差異也含錄音啟動、重取樣對齊誤差，不能稱為 bit-perfect。
- Pause / seek / Restart / Stop、Blackout、凍結觸控、獨看、低頻重量、還原均通過狀態檢查。
- 本機 **FabFilter Pro-R 2 VST3** 成功載入、啟用、錄製約 4.02 s、回到 BYPASS。AU 介面能力由 Max `vst~` 提供，本輪沒有另錄 AU，也未逐一測試所有插件。

見 `session-validation.json`、`media/touch-feedback-demo.mp3`。這是命令注入及音訊量測；没有宣稱手指或人耳主觀驗收。

## 視覺與實機邊界

已目視 Max 的六種構圖選單、五條行為與獨看、Impact 調整面板、播放及原生 MIDI 選單。`preview.png` 比較 Sana 同一時刻的六種構圖；`roles-in-motion.mp4` 是 **17 秒**相同原創輸入的六模式並排影片。首模式為捕捉的 Native RGB，其餘模式重播同一份特徵；均使用正式 Renderer，螢幕額外 gamma 不代表實體亮度。

本輪 Max MIDI 列舉為 none，未完成 Launchpad 實體按鍵、LED 光度或端到端延遲測量。0.1 的實機 inquiry / Programmer layout 回覆保留在歷史報告，不能當新版硬體驗收。自動滑鼠注入因前景狀態變動未完整跑通；已做 UI 視覺檢查及 JSUI callback 測試。

操作與錄音結束後，觀察到主視窗正在播放與切換構圖，保留該狀態。驗收用 `runtime-control` 視窗已關閉。

## 重跑與封裝

一般運行只需 Max。重建需 Node；音訊驗收需 Python / numpy / ffmpeg，圖片／影片需 Pillow。先關閉主 patch，`npm run build`，再開主 patch 與生成的 `tmp/runtime-control.maxpat`。

- 工程：`npm test`。
- 行為：`make-behaviour-fixture.py` → `run-behaviour-check.py` → `verify-behaviour.py`。
- 頻域：`make-role-fixture.py` → `native-acceptance.py` → `verify-native-roles.py`。
- 操作：`run-session-checks.py`（可附最後載入的音檔路徑）→ `verify-session.py`；指定插件未安裝則略過插件實錄。
- 整曲：`run-song-check.py 音檔完整路徑` → `verify-song-trace.py`。

`npm run package` 寫入每檔 SHA-256、建立 ZIP 並重新讀取確認。另解壓至測試目錄，重建並跑 56 組檢查，核對生成檔和原生整曲所測的 SHA-256。正式 ZIP 不含 tmp、原始 Sana MP3 或測試網路接收器。
